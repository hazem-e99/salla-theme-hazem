## twilight.json

- Valid JSON. 58 components, 34 top-level settings.
- **52 of 58 components use non-UUID string keys** (e.g. `premium-system-hero-001`,
  `premium-structured-014`) instead of the UUID v4 format used by all 6 legacy/original
  components (e.g. `186b3f4f-25cf-4d3c-abca-cef7eed6f0ab`). This is the leading hypothesis for
  why Premium sections may fail to register in the live "Add Section" library — see
  `EDITOR_INTEGRATION_REPORT.md`.
- 3 components (`premium-system-hero-001`, `premium-system-products-001`,
  `premium-system-collections-001`) declare a `required: true` dynamic `products`/`categories`
  selector field with an empty `selected: []` / `value: []` default — a second concrete schema
  risk.
- No duplicate component keys, no duplicate component paths, no duplicate field IDs within any
  component, no missing bilingual titles, no invalid icons, no malformed multilanguage field
  values, no dropdown-list fields missing both `source` and `options`.
- Every one of the 58 `path` values maps to a real, existing Twig file under
  `src/views/components/...` — template wiring is not the problem.
- All Premium components are missing the optional `image` (Add Section thumbnail) property that
  every legacy component has — cosmetic, not a rejection cause, but should be fixed for parity.
- The 52 premium components are generated by `scripts/sync-premium-components.mjs`, which was run
  manually (not wired into any `pnpm` script or CI) and its JSON output committed directly. This
  script is the actual source of truth to fix, not the JSON file by hand.
